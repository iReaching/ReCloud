# Android feature parity and verification

Android uses the original app's Home, Search, Library, Now Playing and Settings destinations. Native audio and YouTube have different playback capabilities. This table describes the implementation shipped in the Android source.

## Sync and source limits

Compare all five fingerprint groups on both screens before selecting **Codes match**. Only metadata crosses the network. Each phone retains its audio files, file permissions, API key and account credentials. A valid Android snapshot may be up to 8 MiB and 20,000 songs. The latest edit wins for an entire playlist or favorite, with a deterministic tie-break and playlist deletion markers. Concurrent edits to the same playlist can overwrite one another. Listening counters take the maximum per track and installation, so repeated exchanges do not add the same plays twice.

The YouTube Data API returns a page of up to 50 public search, channel or playlist entries per browse action. The account playlist listing requests additional pages up to 1,000 playlists. In an account playlist, Load more videos requests the next page. Play all, Shuffle all and row selection fetch the remaining pages before cueing the player. Retrying continues at the failed page. Overlapping playlist-item IDs appear once, and separate entries for the same video keep their positions. For mixed playlists, selecting a recording queues entries supported by the same player. A YouTube subscription does not carry native background or download entitlements into this app.

Internet Archive downloads require an item-level recognized Creative Commons license or public-domain declaration, an accessible file and a supported audio format. Item and license links are available in song menus. A provider's catalog, format selection, network response or removed item can affect availability.

## Reproduce the checks

From `android/`, run `./gradlew testDebugUnitTest lintDebug assembleDebug`. With a disposable emulator running, also run `./gradlew connectedDebugAndroidTest`. The instrumentation suite uses temporary databases and exercises media playback, pairing and local settings. Use a test installation because Android's connected test tooling can uninstall the app after a run. HTML reports are generated under `app/build/reports/`. The hosted workflow builds a debug-signed artifact and uploads its reports.


Android 17 verification on 24 November 2026 passed five device tests. Connect Google account reached the Google Play services sign-in screen on an emulator with no configured account. This emulator check stopped at the account chooser. The revised debug build passed nine JVM tests and lint with zero errors.

On 25 November 2026 the account-playlist build passed 12 JVM tests and six device tests on Android 11. A 52-video fixture covers overlapping pages, a failed continuation and repeated occurrences. An emulator WebView test cues 52 IDs and reports the last position using a simulated YouTube player callback. Live playback through the updated queue with a signed-in account still needs a device check. Android lint reported zero errors and ten warnings.

The revised Now Playing screen exposes play/pause, previous, next and seeking for the foreground YouTube player. Play audio files opens the system picker and sends the chosen files to the native Media3 queue. On the Android 17 emulator the original YouTube iframe measured 0 CSS pixels inside a 213-pixel viewport. On Android 11 the rebuilt iframe measured 203 pixels inside a 203-pixel viewport and the same piano recording advanced from 0:00 with the Compose Play button. A picked WAV also advanced in the native player. The WebView regression test now checks the rendered iframe height.

Repeat verification on Android 11 exercised all three modes at the end of a native WAV and in a live two-video YouTube queue. The 202-second piano recording restarted at the beginning in repeat-song mode. At the end of the second video, repeat-queue mode wrapped to the first and repeat-off mode stopped. The WebView tests also cover single-entry queues, shuffled order, repeated video IDs and manual skips.
